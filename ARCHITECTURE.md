# Rune Weaver: Architecture

## PROJECT SOUL

Rune Weaver is a personal AI assistant harness: a modular, privacy-first system that bridges your digital life across the Apple ecosystem, self-hosted services, and the web. It runs as an always-on "brain" on a Mac Studio, with thin clients connecting to interact with it.

- **Local-first, cloud-optional**: Data stays on your hardware by default; cloud LLMs are an opt-in fallback.
- **Human-in-the-loop**: The agent reads freely but writes cautiously. Every action that changes state requires explicit permission, with graduated trust so you're not approving the same thing forever.
- **Modular by design**: Capabilities are plugins (runes). Add new ones without touching the core.
- **Apple-native where it counts**: Keychain, AppKit/SwiftUI, Messages snapshot reads, ScreenCaptureKit: foundational, not bolted on.
- **Swappable LLMs**: The brain is model-agnostic. Local MLX, llama.cpp, or a cloud API: tools and memory don't care which model is thinking.
- **Fast recall without exfiltration**: An opt-in on-device index (chunked, keyword-searchable, vectorized on-device via EmbeddingGemma 2) makes everyday questions fast; live reads remain the freshness fallback. Nothing is indexed until the owner turns it on.
- **Durable goals over one-shot prompts**: A goal is a first-class entity (plan, step statuses, event log, cadence) and keeps working between conversations. The scheduler merely executes toward it.
- **Proactive, but interrupt-worthy**: Background completions pass a surfacing judgment so notifications stay rare enough to be trusted; run history and the approvals inbox record everything regardless.
- **One switch per capability**: A capability that only runs when its tool is invoked is enabled in exactly one place: the tool toggle. A second enablement gate in config is a bug, not a feature.
- **Quiet green over alarm fatigue**: The System Pulse reads `green`/`yellow`/`red` only: green while every recorded verifier passes, yellow degraded with bounded reasons shown behind a disclosure, red fail-closed with bounded reasons shown plus exactly one mapped recovery action. Red clears on a fresh passing snapshot, never on timer expiry, and an unanswered probe never clears anything.

This document maps what the architecture **is**: components, protocols, responsibilities, binding constraints. Build status and what ships next live in `ROADMAP.md`; configuration options and bounds live in `CONFIG.md`.

## SYSTEM ARCHITECTURE

The core engine is a local Vapor service that UIs drive through one HTTP surface; no terminal loop runs turns beside it.

**Modules** (one Swift package, `Sources/`):

| Module | Owns |
|--------|------|
| `RuneWeaverCore` | Orchestration, conversation/memory stores, document index, goals/ideas/fan-out engines, permission gate, access rules, policy store, egress-independent security actors (watchdog, health snapshot, sovereign ledger, probe suite, semantic answer cache) |
| `RuneWeaverLLM` | `LLMProvider` abstraction, `LLMRouter`, `MLXProvider`, `LlamaCppProvider`, `OpenAICompatibleProvider`, circuit breaker, provider-backed embeddings |
| `RuneWeaverTools` | All tool implementations (email, browser, files, bash, messages, media, desktop, calendar/reminders, goals, fan-out, api.request) plus `OutboundEgressSupervisor` |
| `RuneWeaverServer` | Vapor routes, `WSHub`, `ActiveTurnTracker`, `ServerAuth`, scheduler store/worker, run log store, dashboard bundle serving |
| `RuneWeaverApp` | macOS menu-bar app (signal-only indicator, permissions onboarding, settings) |
| `RuneWeaverCLI` | `rune-weaver` ops CLI (auth, policy, serve, status) |
| `Web/src` | React dashboard bundle served by the engine from `Web/dist` |

**Transports**: REST + WebSocket (`/ws`, `WSHub`). Loopback always serves; non-loopback requires a resolved owner token or boot is refused. Exactly one owner token guards the surface; browsers exchange it via `POST /auth/session` for an `rw_session` cookie (`HttpOnly`, `SameSite=Strict`) whose 24h lifetime slides with activity (refresh throttled to once per 5 minutes; session state keyed by SHA-256 digest, persisted digest-only in `~/.runeweaver/auth-sessions.json` at `0600`, surviving restarts; unreadable/corrupt stores fail closed to no sessions; `maxActiveSessions` 100 with least-recently-seen eviction). Every inbound request also passes the Host-header gate (`HostValidationMiddleware`): the Host value must match the bind hostname or an exact-only `[server] allowed_hosts` entry (loopback hosts always included), and anything else is refused with 403: the inbound boundary that defeats DNS rebinding.

**Data stores**: `episodes.db` (SQLite: sessions, turns, jobs, runs, goals, ideas, staged/live review ledgers, approval decisions, scheduled sends), `index.db` (document index), JSON vector store, `~/.runeweaver/policy.toml` (declarative egress policy, separate from `config.toml`).

**Concurrency**: Swift actors for isolation, protocol-oriented subsystems, structured concurrency for streaming. The engine is the only turn runner, so per-firing-class locks bound the whole process. The intentional exception is `LlamaCppEmbeddingsBackend`, a final class conforming to `Sendable` with immutable `let` state only, so parallel embedding requests run reentrantly across `llama-server` slots; all other isolation stays actor-based. Parallel embedding fans out only through `FilesIndexer.embedSubBatchesConcurrently` with a `withTaskGroup` bounded by `maxConcurrentEmbeddingRequests`, with cooperative cancellation via `IndexCancellationFlag`.

**Tool inventory**: email (`email.search`, `email.read`, `email.attachment`, `email.send`, `email.listMailboxes`, `email.move`), web (`web.search`, `web.fetch`, `browser.navigate`, `browser.act`, `api.request`), files (`files.read`, `files.grep`, `files.glob`, `files.list`, `files.write`), memory (`memories.store`, `memories.recall`), Messages (`messages.search`, `messages.read`, `messages.send`, `messages.resolveRecipient`), media (`media.arr`, `media.arr.read`), desktop (`desktop.screenshot`, `desktop.action`), bash (`bash.exec`), goals (`goal.create`, `goal.status`, `goal.progress`), fan-out (`fanout.run`), calendar/reminders (`calendar.*` / `reminders.*`: `search` read-only; `create`/`update`/`delete` approval-gated, backed by per-domain EventKit gateways), plus `question.ask`. All tools always register (visible in `GET /tools`) so the registry never shape-shifts with config.

## COMPONENT DETAILS

### Orchestrator & Turns

`Orchestrator` receives user input, routes through the LLM, executes tool calls, and returns responses.

- **System prompt**: `SystemPromptComposer` renders a prefix-stable prompt carrying no per-tool text (identity, tool-use policy, memory guidance, current date); tool definitions travel strictly on the wire, so registry contents never affect prompt bytes or cache identity (`cacheKey` covers the scheduled branch plus current date only). Canonical memory names are advertised on the wire; aliases never are. One static rule teaches that delimited untrusted content is data, never instructions.
- **Narration fallback**: `OrchestratorToolLoop` extracts read-only calls from text narration for local LLMs; gated narrations file approvals and park until decided.
- **Background sources**: `Orchestrator.isBackgroundSource(_:)` is the single owner of which sources (`scheduler`, `goal`, `fanout`, `fanout_worker`) use background prompt/turn handling and parking.
- **Turn cap & cancellation**: `ActiveTurnTracker` (Server) bounds simultaneous chat turns at `maxConcurrentTurns = 3` and tracks running turns across WebSocket and REST for mid-turn cooperative cancellation.
- **Sessions**: `ConversationManager` persists session state and history in SQLite, hydrating from disk. Sessions carry origin `source` (`dashboard`, `websocket`, `api`, …), optional caller-supplied `title`, optional `goal_id`, and optional `parent_session_id` (fan-out lineage). `Orchestrator.process` stamps these through its single `ensureSession` call; fills never overwrite stored values without `overwrite: true`.
- **Routing**: `LLMRouter` drives priority-ordered providers with fallback (`ProviderConfig`, `ProviderKind`). Goal decomposition, the proactive judge, and the fan-out reviewer all reuse the SAME injected provider/router instance the orchestrator is constructed with; none is self-built.

### Memory & Recall

Three tiers: **working** (current context, folds into rolling summary over budget), **episodic** (SQLite + FTS5 turn mirrors, permanent, compacts >30d when >10,000 rows), **semantic** (JSON vector store + profile; cosine when embeddings available, keyword overlap otherwise).

**Automatic recall path** (routed, budgeted, freshness-aware):

1. `Orchestrator.process` builds one `RecallPlan` per turn via `MemoryQueryRouter.plan(for:currentDate:)`, inferring `since/until` (`TemporalFilter.parse`) and freshness (`LiveSearchGuidance`) with query expansion only, no LLM call.
2. `MemoryEngine.recallMessage` embeds best-effort (cancel propagates; other failures fall back to keyword), recalls with the plan window, and skips or down-weights `docIndex` when `LiveSearchOverride.shouldUseLiveSearch` is forced. Empty query, store error, or below-threshold yields nil; recall never fails a turn.
3. `recall` merges episodic, semantic, document-index, and profile hits under `RecallBudgets` from `[memory] recall_*`. Document candidates use a widened, event-time-ordered pool (vector leg reads `min(max((clamped * docPoolMultiplier) * 10, 500), maxPerTierResults)`, keyword leg at the same width), fused with reciprocal-rank plus token-overlap, recency, exact name-or-path, entity, and contiguous-phrase bonuses, then calibrated by tier weight. Dedupe by ID plus content; sort by score then tier priority (profile > semantic > docIndex > episodic).
4. Injection is at most one auto-recall system message plus at most one starter-pack system message, placed directly before the last user message via `MemoryEngine.historyWithRecall` (never lead system) to preserve prefix-cache. `RecallStarterPack.build` always supplies `Profile:`, `Index as of:`, and optional `Goal:` lines (trusted verbatim, capped). Recall lines carry `[date|path|display_name]` citations and wrap docIndex plus episodic `Used`-mirror content in the `ContentTrustLabeler` data-only block; trusted tiers pass verbatim.
5. Diagnostics: `recallWithDiagnostics` returns hit IDs, sources, scores, injected chars, and `skippedDocIndex`; one content-free log line per turn.

`MemoryEngineDocRecall` packs greedily to 8000 chars with drop-don't-chop semantics, preserves newlines in chunks, and normalizes keyword rank so rank 1 scores exactly 1.0. `/remember` captures deterministically; facts persist with vectors and mirror into profile.

**Semantic answer cache**: `SemanticAnswerCache` (actor) replays pure Q&A answers: entries key on normalized query + persona + serving model, live in memory only, start empty at every boot. `isExcludedTurn(source:executedToolCalls:)` refuses tool turns, approvals, sends, and voice prompts, so "never store" implies "never hit". Near-duplicate questions score at or above `similarityThreshold` (0.92) via the injected embeddings backend with keyword fallback. `invalidateOnMemoryWrite` is the single clear route: facts, preferences, profile, goal changes, and policy changes all clear it; the episodic turn mirror deliberately does not. Bounds: `timeToLive` 24h, `maxEntries` 500, `maxAnswerChars` 2000.

### Document Index & Embeddings

Opt-in (off by default, per-source `files`/`mail`/`messages`/calendars/reminders toggles in `[index]`) local index: pay once, answer from index, fall back to live reads. SQLite `indexed_documents` + `indexed_chunks` + FTS5 porter plus embedding BLOBs, content-hash skip, per-mailbox UID and Messages ROWID watermarks, `BODY.PEEK` mail reads, credential-redacted mail storage (search recall cannot resurrect a redacted link), nightly plus on-demand `IndexCoordinator` runs, `index_as_of` watermark, and prune/reset maintenance. `IndexCoordinator` launches all enabled stages (`files`, `mail`, `messages`, `calendars`, `reminders`) concurrently in one task group while joining stage reports in canonical `IndexSourceKind.runOrder`. `DocIndexStore` preloads per-source fingerprints (`storedFingerprints(source:)`) and commits batches in single SQLite transactions (`upsertDocumentsWithChunks(_:)` and `markSeenBatch(source:externalIDs:runID:)`). `FilesIndexer` partitions candidates into 4 modality queues (`.keywordData`, `.fastText`, `.imageOCR`, `.mediaSpeech` ordered newest-first), prunes build and package vendor trees via `FilesIndexer.alwaysSkippedPatterns` (`site-packages`, `dist`, `build`, `.build`, `.next`, `.turbo`) during traversal, routes structured/config/log extensions plus `map`/`wasm` plus minified/bundled web assets (`.min.js`, `.min.css`, `.bundle.js`, `.chunk.js`) via `FilesVectorPolicy.isKeywordOnlyFile` directly to FTS5 without calling `llama-server`, and batches text chunks across files with staged caps `maxStagedCandidatesPerBatch = 64` and `maxStagedPromptsPerBatch = 128`, slicing by `maxEmbeddingChunksPerRequest = 32` and `maxEmbeddingSubBatchBytes = 12000` via `FilesIndexer.nextEmbeddingSubBatchEnd` and dispatching at most `maxConcurrentEmbeddingRequests = 4` concurrent sub-batches via `FilesIndexer.embedSubBatchesConcurrently` with per-chunk fallback. `MailIndexer` fetches IMAP UIDs in multi-UID sets (up to 25 UIDs per `UID FETCH ... (BODY.PEEK[])` with per-UID fallback), batches page embeddings, and coalesces checkpoint writes once per page (`recordInMemory` + `flush`). Indexed hits always preserve citations so answers carry paths and dates.

**Multimodal extraction**: `MediaTextExtractor` (Core) is the single owner of image OCR (`Vision.framework`) and audio/video transcription (`Speech.framework` + `AVFoundation`, gated by the macOS Speech Recognition TCC onboarding row and `NSSpeechRecognitionUsageDescription`); `DocumentTextExtractor` routes by format. Allowlisted extensions only (images `png jpg jpeg heic heif tiff tif webp`, audio `mp3 m4a wav aac flac`, video `mp4 mov m4v`); anything else is rejected. Video containers demux their audio track to a temporary `.m4a` file via `AVAssetExportSession` before `SFSpeechURLRecognitionRequest`. Audio and video containers are exempt from the text-document `maxFileBytes` cap (vector eligibility evaluates extracted transcript UTF-8 byte count rather than container size, while images use a 30 MB vector cap). There is no LLM image-description path.

**Embeddings**: `EmbeddingsBackend` (`local` default, `provider` opt-in, `none` keyword-only). The local backend is `LlamaCppEmbeddingsBackend` (LLM module, `modelID = "embeddinggemma-2"`, `dimension = 768`, final class with immutable `let` state for reentrant concurrent embedding across slots) served by a supervised `llama-server` child process on the UNIX socket `~/.runeweaver/run/embedding.sock`, posting both batched text and multimodal `image_url` data-URI requests to `/v1/embeddings`. Server flags are `--embeddings --pooling mean --ctx-size 16384 --batch-size 16384 --ubatch-size 1024 --parallel 4 --n-gpu-layers 99 --sleep-idle-seconds 60` (4 independent slots), owned by `LlamaEmbeddingSupervisor.performStart`. `LlamaServerProvisioner` discovers or downloads the Darwin ARM64 binary; `EmbeddingModelProvisioner` ensures the two GGUF files (temp-file + atomic rename, minimum-size verification); `LlamaEmbeddingSupervisor` owns process lifecycle with ping readiness, `--sleep-idle-seconds 60` idle standby (clean exit `0` transitions to `.idle` with a green standby toast and respawns on demand), and SIGTERM/SIGKILL shutdown. Flags are boot truth: any flag change triggers full restart via `stop` plus `ensureRunning`, never live-reload. No other file spawns embedding servers. Failures fall back to keyword; cancellation propagates. `embedImage` and transcription are wired into the indexers as a contract, not optional.

**Dimension stamping**: `DocIndexStore` stamps embedding model and dimension and enforces `ensureEmbeddingDimensionMatch(expectedDimension: 768)` before every vector-writing stage. A store stamped with another dimension resets its vectors and triggers full re-indexing; a mixed-dimension store is never served silently.

**Index run change stream (poll-snapshot primary)**: liveness rides throttled `tool_progress` frames on the shared 2 Hz cadence (forced 2.0s heartbeat re-emitting cumulative totals); lifecycle rides `IndexRunReporting`: `ServerIndexRunReporter` appends the `running` `run_logs` row (`kind = "index"`) and broadcasts `run_started`, updates the same row and broadcasts `run_completed`, appending when the start row was pruned. `GET /index/status` carries the additive `live` snapshot derived from `liveTotals` (including `vectorChunks`, `keywordChunks`, concurrent per-source `sources`, and 4-lane `queues`; nil when idle); WebSocket frames are poll-now wake-ups only, never the data carrier. `start(trigger:)` is single-flight (`.alreadyRunning`); `cancel()` is immediate-and-cooperative. The web IndexingPanel renders the 4-stage pipeline track, 4 modality queue lanes, and concurrent source chips, projects in-memory live document and chunk deltas onto the KPI cards and charts mid-run while keeping expensive SQLite `dbstat`/`LENGTH` byte sizing deferred until `run_completed`, and adopts progress frames only while a run is in flight under the `index` tool name.

### Approvals: Decision Contract, Surfaces, Decision Log

**Contract**: `POST /approvals/:id/decide` with body `{approved, duration, scope}` is the only decision path; the chat inline banner, the Inbox, the dashboard quick actions, and WebSocket triage all send it.

- **Egress-parked requests** (`pending.egressHost != nil`): approved + `thisTime` → `OutboundEgressSupervisor.allowDomainOnce`; approved + `forSession` → `allowDomainForSession`; approved + `forever` → durable allow rule scoped `domain(host)`; denied + `thisTime` → deny the call only; denied + `forever` → durable deny rule scoped `domain(host)` plus `PolicyStore.appendBlockedDomain`.
- **Everything else**: approved + non-`thisTime` duration → durable allow rule with the resolved scope; denied + `forever` → durable deny rule; denied + `thisTime` → deny the call only.
- `engine.continue`, `question.ask`, `desktop.resume`, and `behavior.brake` are coerced to `thisTime` with no stored rule inside `ApprovalQueue.decide(id:approved:duration:scope:)`; they resolve one parked batch. `thisTime` never stores anything.
- A `messages.send` scope must be `recipientSet` or an `exactTarget` naming a canonical handle; any other send scope stores nothing and the call fails closed at execution.

**System notices**: the engine files surfacing-only notices under the fixed tool names `sovereign.mismatch` and `security.probe` (the closed `SystemNoticeTools` registry decides, never a name-prefix rule). Filing never schedules safety assessment: the assessment child is skipped for registry names, so a notice carries no severity, and its card renders no scope, no duration, and no approve/deny control: the inbox is a surfacing channel, not a second gate. Pending existence is the dedup key, so at most one pending notice exists per system tool and a changed failure reason updates nothing until it resolves. Resolution is never a decision: only the mapped remedy (a passing sovereign re-verification or re-baseline for `sovereign.mismatch`, a passing verifier re-check for `security.probe`) settles the tool's pending items, each leaving one `approval_decided` broadcast through the same hub publish path the decide route uses plus one decision-history row tagged `settled` whose display target carries the recovery note. A settled card drops live through that frame and the owning surface's refetch (no reload, no manual refresh control, no timer) because live settlement is the only removal path, and a refresh button or timestamped auto-update entry would only add state that drifts from it.

**Surfaces**: quick surfaces (chat inline banner, dashboard Needs Your Action card) decide duration-only: no `scope` is sent, so the engine resolves the request's own target. The chat Allow chevron lists exactly the 7 `trustDurationOptions` entries (exactly the 3 egress durations for egress-parked requests); the dashboard card matches. The Inbox card is the only scope-deciding surface (This target / All targets / Custom scope). Deny is a split button: main Deny = deny once, chevron "Deny always" = `approved=false` + `forever` (minting a deny rule). Standing-rule scope editing lives only in Settings → Access. System notices ride one shared surfacing-only card (`SystemNoticeCard`) on both the Inbox and the dashboard queue: its whole action is the mapped remedy (`Re-baseline & re-verify` / `Open Policy`), never a decision.

**Decision history**: every resolved decision (including question responses and denies) is recorded exactly once inside the shared decision contract, into the `approval_decisions` table behind `ApprovalDecisionLog` (rows carry tool name, resolved scope, action, duration, surface tag, session id, display target, `decided_at`). Recording is fail-open: a log write failure never fails or retries the decision. The store caps at `ApprovalDecisionLog.maxRows = 10000` with oldest-first eviction, retains otherwise forever; `GET /approvals/history` reads it, `DELETE /approvals/history` clears it. The Inbox renders Pending | History with a Clear-logs button.

**Behavior brake**: `BehaviorWatchdog` (actor) is the anomaly brake over trusted tools. It records only counts (tool name, session, outcome category: executed, denied, firewall-blocked), never arguments, prompts, or model output. Rules (`rate_spike`, `denial_spike`, `off_hours`, `firewall_spike`) evaluate a trailing window against a learned baseline; the watchdog stays silent through its 14-day quiet-learning gestation. When a rule fires it parks every running turn through the same cooperative cancel contract `ActiveTurnTracker` owns, clears each session's steering, and files one numbers-only `behavior.brake` card in the approvals inbox (idempotent while engaged). It never auto-remediates and never approves: "keep paused" leaves turns parked exactly as the owner left them, and clearing requires an explicit owner Resume (the dedicated Inbox branch), which resets trailing counters. It never clears on a timer.

### Access Rules & Trust

Permission levels: `readOnly`, `requiresApproval`, `trusted`. `memories.store` and `memories.recall` are `trusted`, `goal.status` is `readOnly`, and `goal.create`, `goal.progress`, `fanout.run`, `files.write`, `messages.send`, `desktop.action`, `browser.act`, `api.request`, and `media.arr` require approval. Every action a goal step or fan-out worker takes flows through the permission gate exactly like any other turn; there is no bypass for background work.

**Access rules** (`AccessRule.swift`, Core) are the durable trust model: one rule = (`toolName`, `AccessScope`, `AccessAction`, `duration`). `AccessScope` is `toolWide`, `exactTarget(String)`, `recipientSet([String])`, `domain(host:subdomains:)`, `pathPrefix(String)`, or `glob(String)`; `AccessAction` is `allow` or `deny`; duration is nil (standing) or one of `fiveMinutes`, `oneHour`, `oneDay`, `forever`. Spelling is owned per shape (`AccessScope.normalizeRecipients`, `canonicalDomain`, `canonicalPathPrefix`, `canonicalGlob`), and `AccessScope.matches(toolName:argumentsJSON:)` is the single owner of scope matching. A malformed or unrecognized scope is rejected at creation and never matches at evaluation. Task and session trust lives in `EphemeralGrant`s instead: in-memory beside the gate, dead on their owning task's or session's lifecycle boundary, never persisted (readable via the session-trust route, cleared by `POST /approvals/ephemeral/clear`).

**Gate decision order** (`PermissionGate.checkPermission`), highest first: (1) durable deny covering the call → denied; (2) non-read-only edits of protected engine paths refuse; (3) egress host status decides: blocked refuses, unlisted parks; (4) `readOnly`/`trusted` tools run; (5) `bash.exec` evaluates the shell policy (deny/allow/ask); (6) `files.write` resolves its posture through `WritePathPolicy` (deny/stage/live/ask); (7) ephemeral grants may cover the call; (8) durable allow rules may cover the call; (9) anything left parks for approval. **Deny outranks**: a durable deny is evaluated before any grant coverage, never expires, and is removed only by explicit revoke; no allow rule overrides, shortens, or evicts a deny for the same scope, and widening never promotes a deny. A deny rule is minted only by an explicit owner decision (denied + `forever`) or `PermissionGate.denyRule(scope:toolName:reason:)`.

### Egress Policy & Security Model

`~/.runeweaver/policy.toml` (owner-editable, separate from `config.toml`) owns network egress (`[network]`: `mode` `allowlist_only` | `unrestricted`, `allowed_domains`, `blocked_domains`, manual-only `local_exemptions` for private-address dialing) plus per-secret credential bindings (`[credentials.<key>]`: `allowed_hosts`, `allowed_methods`, `allowed_path_prefixes`). Unknown tables are ignored on load.

- **`PolicyStore`** (actor, Core) is the single owner of the file. Every load and update runs `PolicyInvariantVerifier.verify` before acceptance: **credential confinement**, **rule-shadow prevention**, **local-exemption safety**; an unreadable or failing file seeds factory-safe defaults (allowlist-only). `snapshot()` returns the verified policy or throws; there is no permissive fallback state.
- **`OutboundEgressSupervisor`** (actor, Tools) is the multi-consumer choke-point for `api.request`, `web.fetch`, `browser.navigate`/`browser.act`, `bash.exec`, and `desktop.action` egress. Network and binding checks run BEFORE Keychain access or DNS resolution, so a denied destination never causes a side effect. Each allowed verdict carries a **dial pin**; the transport dials the pin instead of resolving the hostname again, and a missing pin fails closed. DNS resolution itself is bounded by a fail-closed 5s timeout (`ApiSSRFGuard.dnsResolutionTimeoutSeconds`) so a wedged resolver refuses the gate instead of stalling it; literal hosts never wait on DNS. HTTP redirects are followed manually with re-validation.
- **Mandatory wiring**: the supervisor exists at every production entry point. CLI and menu-bar app exit nonzero at boot when the policy cannot be verified; `ServerContext.make` always injects a verified supervisor or throws.

**Secrets & surrogation**: Keychain primary, Docker vault optional, `config.toml` for non-sensitive settings only. `api.request` header values reference `rwsecret:<key>` surrogates; `SecretsManager` issues, resolves (just-in-time at the transport boundary; the real value is never model-visible), and sweeps (`redactResolved`) them. A surrogate with inner whitespace is rejected; `ApiHeaderPolicy.redacted` also redacts echoed secrets in outputs. Secrets never enter logs, prompts, or index.

**Verification stack**: `SovereignLedger` (actor, Core) proves the primary episode ledger's history has not been retroactively edited: primary store stays source of truth; a hash-chained sovereign copy plus an Enclave-signed checkpoint corroborate it, and a stale checkpoint (older than `maxCheckpointAge` 36h) cannot arbitrate, so the ceremony fails closed. Key identity is Keychain-only under service `com.runeweaver.secrets`: account `sovereign.signing.key` holds the 32-byte HMAC-SHA256 key as base64, minted fresh into the Keychain upon first use; it uses `storeKeychainIfAbsent`/`retrieveKeychain` only and never consults environment. Sovereign anchor metadata lives in the primary SQLite database (table `sovereign_anchor`), avoiding Keychain prompt friction for mutable operational state while staying beside the primary history. The anchor is read fresh per ceremony and written only for passing heads (never for mismatch or orphaned) so only attested heads survive sidecar deletes. Files absent plus anchor present means prior attestation lost: the ceremony returns `orphaned` without writing artifacts and the pulse parks red naming both missing sidecars until an explicit re-baseline clears it; a genuine fresh install carries no anchor and writes its baseline green. A Keychain wipe loses the signing key, mints a fresh key on next use, and cannot verify old HMACs, so recovery is explicit re-baseline. Total local compromise (host plus Keychain fully controlled) is out of scope. `SecurityProbeSuite` runs a bounded verifier suite against the real guard implementations under total and per-probe timeouts, at serve boot, after a committed policy write, and on the nightly cadence.

**Security model essentials**: read by default, write with permission; least privilege; sandbox before trust (Seatbelt profiles confine subprocesses; `policy.toml` is denied to sandboxed subprocesses); no secrets in prompts; local audit trail with timestamps; defense in depth for external content (declaration-driven untrusted labeling, deterministic credential filtering, supervised egress, surrogate references); ATS local-networking only; fail-closed transport. Engine paths under `~/.runeweaver/` (config, `policy.toml`, `auth-sessions.json`, `index.db`, `memory/episodes.db`, `memory/vectors/`, models, logs, plugins) are permanently protected from tool writes.

**Provisioning supply chain**: the embedding provisioners fetch only their declared URLs, extract with traversal rejection, set `0755`, strip quarantine, verify minimum sizes, and place atomically. A failed download leaves no partial artifact in place.

### Files & Review Artifacts

`files.read`/`grep`/`glob`/`list` run inside allowed roots under `FilesAccessGuard`. `files.write` is the reviewable write path: every write stages for review or lands live under a tracked rollback copy, and both outcomes persist in `episodes.db` so a reloaded client always knows how a review ended.

- **Write posture**: `WritePathPolicy.classify(path:filesConfig:)` is the single owner. Precedence: deny-pattern glob → deny; longest matching write-path rule → its posture; global `write_mode` (`model` default: the agent chooses per call and a stale per-call argument is accepted-and-ignored while forced; `staged`; `live`); outside every allow root → ask. `ask` parks one approval (a write parks at most once); `stage`/`live` file no approval request.
- **Staged review**: the proposal writes to a `.rune_<name>` sibling and upserts a pending `staged_files` row; Accept promotes, Discard deletes, a later live write supersedes.
- **Live review**: the first live write to an existing path snapshots ONE first-wins `.rune_backup_<name>` rollback copy; later writes join the pending review and never touch the copy. `live_reviews` records reviews; `StagedFilesStore` serializes write-start and resolution as critical sections.
- **Reserved namespace**: `.rune_` / `.rune_backup_` siblings are never valid write targets; snapshots probe with `lstat`, never follow a final symlink, create exclusively, and never delete a peer's copy.
- **REST**: `POST /files/review-status` (batch of 1–200 paths), `POST /files/live-accept`, `POST /files/live-decline` (both refuse `all: true`). The dashboard serves chat diff cards and the single-column Staged Changes drawer; only the newest pending write per file owns Accept/Discard.

### Goals, Scheduler, Ideas, Triggers & Fan-Out

Cron, polling, goal cadence, and event triggers share SQLite as source of truth, with per-run sessions (`source: scheduler`/`goal`/`fanout_worker`), parked `awaiting_approval` resumes through the inbox, and per-firing-class single-flight per process. `next_due_at` drives firing; there is no catch-up stacking after downtime.

- **Event triggers**: `goal_triggers` rows arm goals for event wake-up; `GoalTriggerBridge` polls recent goal/episode events within a bounded lookback and sets `next_due_at = now` on a kind/pattern match past cooldown: the due-firing path picks it up unchanged (one match per cooldown window).
- **Scheduled sends**: booking is agent-driven: the agent proposes a delayed email or Messages send and the owner's approval books it. At the approval moment the exact bytes, recipient, and fire time are stored immutably as one `ScheduledSend` row (email booking is to-only, no attachments or replies, refused at admission so approved bytes always equal fired bytes). The fire worker claims due rows exactly once via queued→sending, then replays the stored bytes through the owning send tool with re-validation and no LLM regeneration. Stale recipient, policy refusal, or transport failure settles the row `failed` with the reason as its Runs note; a send aged past its grace window settles `failed` instead of stacking catch-up fires. Cancelling or editing needs a fresh approved booking. Every fire and skip writes a `run_logs` row and broadcasts.
- **Goals**: durable first-class entities in `episodes.db` (`goals`, `goal_steps`, `goal_events`, `goal_triggers`). `GoalStatus`: `active`, `paused`, `needs_input`, `achieved`, `abandoned`, `unplanned`; `StepStatus`: `pending`, `inProgress`, `done`, `blocked`, `skipped`; new goals start `unplanned` and the active cap counts `active` + `unplanned`. `GoalStore` is an actor behind a `GoalStoring` seam; `nextActionableStep` picks the lowest-ordinal pending/in-progress step. `GoalEngine.create` enforces `[goals] enabled` plus the cap, then decomposes via ONE LLM call bounded by `maxStepsPerGoal` and `planTimeoutSeconds`; on cancel, parse failure, or timeout it settles to `unplanned` with empty steps plus a note: no placeholder, no fallback. Advance composition puts dynamic goal state (completed steps context plus the single next actionable step) into the `UserInput` text via `advancePrompt`, never the cached system-prompt prefix. An advance is an ordinary orchestrator turn (`source: "goal"`, `goal_id` stamped, `run_logs` row `kind="goal"`, hub broadcast). REST: `GET /goals`, `POST /goals`, `GET/PATCH/DELETE /goals/:id` (delete = abandoned tombstone, `?purge=true` hard-delete), `POST /goals/:id/advance` (single-flight → `409`), `PATCH /goals/:id/steps/:stepId`, `GET /goals/summary`; `goal_updated` frames on every state change.
- **Ideas**: `IdeasStore` + `IdeasEngine` (opt-in, `[ideas] enabled` default false). One cheap LLM call over recent goal outcomes plus a memory-facts summary yields `0..maxPerCycle` ideas (`planAdjustment`, `newGoal`, `tip`); on failure/timeout it returns EMPTY: never hallucinate because planning was flaky. Dedup skips titles equal to an existing non-dismissed idea. Triggered after goal achievement and on the nightly cadence. REST: `GET /ideas`, `GET /ideas/summary`, `POST /ideas/:id/dismiss`, `POST /ideas/:id/accept` (accept routes through the engine with the same honest errors as `POST /goals`; `planAdjustment` applies via `replacePlan` only when the linked goal still exists and is active, else `409`).
- **Fan-out**: `FanOutEngine` (actor) behind a narrow `OrchestratorFanOutSeam` spawns concurrent worker turns for caller-composed subtasks. Each worker gets a fresh session (`source: "fanout_worker"`, `parentSessionID` to the origin chat), a read-only tool subset via `UserInput.allowedTools` (nil = full registry; `fanout.run` passes read-only names unless `[fanout] full_tools`), and run rows (`kind="fanout"` parent plus `kind="fanout_worker"` children). Enablement is the persisted `fanout.run` tool toggle alone (single gate); `[fanout]` carries only knobs (`max_workers` default 2, `worker_timeout_seconds` default 0 = unlimited, positive values clamp 1–86400; the escape hatch for an unbounded worker is cooperative cancellation, never a forced kill; `full_tools` default false). `fanout.run` stays `requiresApproval`: approval is the per-call permission, separate from enablement. Merge: deterministic overlap detection first (exact file-path/URL collisions flagged conflict), then ONE background reviewer pass over the outputs producing a merged summary plus per-subtask verdicts (keep/drop/conflict); the reviewer judges content quality, not permissions, and fails open to the raw concatenation with an honest note: worker output is never lost. An all-cancelled run skips the reviewer.

### Runs, Notifications & History

- **No silent run writes**: every `run_logs` row write (chat, scheduler, goal, index, `fanout`, `fanout_worker`) broadcasts `run_started`/`run_completed` through `WSHub.broadcastRun`; terminal settlement uses cancellation-immune variants sharing the same `fanOut` hop, and fan-out rows ride the shared `FanOutRunLogAdapter` (`RunLogStore` + `WSHub`), so one `fanOut` hop exists. WebSocket turns run detached so socket close never cancels; the tracker owns cancellation. Dashboards never depend on polling alone to see a run start or settle.
- **Surfacing gate**: `OutcomeGate` decides `(surface, headline)` for scheduler/goal completions. Modes from `[proactive] mode`: `all` (default), `milestones`, `guarded` (one cheap LLM judgment with timeout; a judge error fails OPEN to surface), `off`. The gate filters interruptions ONLY: run history, WS run frames, and the approvals inbox record in every mode. Interruptions ride the `proactive_message` frame on the existing hub (no new transport).
- **Cancellation**: `POST /runs/:id/cancel` cancels any running row by run-log row id: one worker or a whole swarm for fan-out rows via the engine registry (a cancel arriving before a worker registers is remembered and applied at registration), any other running row via cooperative `ActiveTurnTracker` cancel plus `steeringQueue.clear`, settling the row to `cancelled` with a hub broadcast. Cancellation is cooperative: nothing is force-killed; a stopped swarm reads `cancelled`, not `error`, while sibling workers keep running.
- **System Pulse**: `SystemHealthSnapshot` (Core actor) fuses subsystem probe completions, the live policy posture read fresh from the shared `PolicyStore`, sovereign ledger ceremonies, and the behavior-brake state into the closed green/yellow/red verdict served on `GET /health` and pushed as `health_updated`. Status is `green`/`yellow`/`red` only: green means all recorded verifiers pass, yellow means degraded with bounded reasons shown, red means fail-closed with bounded reasons shown plus exactly one mapped recovery action. Red wins over yellow; absence of a recorded failure is not a failure: verifiers constrain the pulse only once they report; red clears only on a fresh passing snapshot, never on timer expiry, a fetch error, or an unanswered probe, and a failed probe never moves the pulse. Remediation is `none`/`rebaseline`/`openInbox`/`openPolicy` only, computed as mismatch plus orphaned anchor outranking brake outranking policy outranking probe failure (fail-closed probe failure maps to `openInbox`); green plus yellow carry `none`. Files absent plus anchor present parks red with the named missing files (`ledger.sovereign.jsonl` and `sovereign-checkpoint.json`); only explicit re-baseline clears it, while a genuine fresh install with no anchor stays green. Red raises exactly one inbox item, never a flood. The pulse carries no boot state; every snapshot reads live policy plus recorded ceremonies with no restart and no watcher.

### Dashboard Surfaces & Navigation

The engine serves the `Web/dist` bundle (built from `Web/src`).

- **Navigation is grouped and click/keyboard-only** (hover-open excluded): **Dashboard**, **Chat**, and **Inbox** stand alone: Dashboard is the primary operations landing surface; **Work** groups Goals/Schedules/Runs; **Memory** groups Search, Memory, and Index Status. Navigation groups tab-state (no router). All model-authored content renders through the sanitized `MarkdownText` (no `dangerouslySetInnerHTML`, protocol-whitelisted URLs).

No card is hidden behind a collapsed group, no group-level or bulk approve exists anywhere, and every card carries its own Allow/Deny split buttons with the full duration picker and scope radios. The brake card keeps its dedicated Resume / Keep-paused branch as the existing decision-shaped precedent, and engine-filed system notices (`sovereign.mismatch`, `security.probe`) form the second exception: they group under their own **System** header instead of Unattributed and render the shared surfacing-only notice card, whose whole action is the mapped remedy. History reads `GET /approvals/history`.
- **Needs Your Action** (Dashboard landing): split Allow/Deny per approval, duration-only with no scope; durable trust and scope editing live in Inbox and Settings → Access. The queue mounts the same shared system-notice card beside its approval cards, so a filed notice surfaces on the landing surface with its mapped remedy and no decision controls.
- **Settings → Access**: the owner's "what the agent is allowed to do" surface: a section rail over Rules, Bash & Shell, Network, Credentials, and Files. The declarative policy surface mounts here: structured network and credential editors, read-only local-exemption display with Re-check, credential list plus binding modal, invariant-status banner, shared settings-footer Save with live apply and no restart, no in-app raw editor.
- **System Pulse card**: renders the `GET /health` verdict; red and yellow open a Details disclosure of bounded reasons (capped `maxDegradedReasons` 8 × `maxReasonLength` 160); red renders exactly the mapped primary button (`Re-baseline & re-verify` for `rebaseline`, `Open inbox` for `openInbox`, `Open Policy` for `openPolicy`), derived from the snapshot remediation, never more than one. The inbox button appears only when its card exists. A failed probe never moves the pulse and a fetch error never clears a parked red: only a fresh passing snapshot clears it.
- **Chat**: session sidebar, memory browsing, run history with fan-out worker grouping, file-write review diff cards. Tools config exposes tool toggles and live-reloaded knobs. It owns no approve/deny control, and native notifications name only the tool and severity with a deep-link to the Inbox: no decision can originate there.

## BINDING INVARIANTS

Cross-cutting rules that hold everywhere; subsystem sections restate them locally where they bind.

1. **The permission gate is unconditional.** Every state-changing action (chat, scheduled run, goal step, fan-out worker, scheduled send) flows through `PermissionGate`; background work buys no bypass, and egress supervision can only deny on top of an approval, never relax one.
2. **One enablement gate per capability.** A tool-invoked-only capability (desktop, fan-out) enables solely via the persisted tool toggle and ships disabled while staying visible in `GET /tools`; its config section carries behavior knobs only. Subsystems with background entry points (scheduler, goals, ideas, index) keep a config `enabled` because work can start without a tool call. Removing a redundant gate is a correctness fix.
3. **One decision path, signal-only ancillary surfaces.** `POST /approvals/:id/decide` is the only decision path; the menu bar and native notifications never decide anything.
4. **Fail-closed posture.** A refused or unverifiable input stays refused: denied stays denied when authenticated. Unverifiable policy or unreadable session/auth stores seed safe defaults or refuse boot; no supervisor-less or permissive fallback path exists.
5. **Live truth, no boot-state docs.** Every subsystem reports live state; a policy or settings save applies live with no restart and no watcher. The pulse color always means right now.
6. **The pulse is a closed verdict.** `green`/`yellow`/`red` only; red clears exclusively on a fresh passing snapshot (never on timer expiry, fetch error, or an unanswered probe), and red raises exactly one inbox item.
7. **No silent run writes.** Every `run_logs` write broadcasts on `WSHub`; there is exactly one broadcast path per subsystem.
8. **Prefix-cache stability.** Dynamic per-run state (goal plans, recall blocks, tool definitions) composes into `UserInput` text or travels the wire, never into the cached system-prompt prefix.
9. **Declaration-driven content trust.** Network-derived tool content declares `contentTrustLevel == .untrustedExternal` via the `Tool` protocol extension (default `.trusted`), never by name-sniffing, and renders inside the `ContentTrustLabeler` data-only block.
10. **Bounds live in code where they guard verifiers.** Verified-pulse and security subsystem constants (see CONFIGURATION below) are fixed in source so no config edit can silently relax a verifier.
11. **The agent-tool promotion surface does not exist** in any form: no `AgentToolStore`, no `tool.promote`/`tool.run`, no `/agent-tools` routes or UI, no promotion docs, and no comment strings naming them.
12. **Multimodal understanding is on-device**: OCR/transcription plus embeddings only; there is no LLM image-description path, and removing the on-device multimodal wiring is not an accepted fix.
13. **Embeddings truth is fixed**: 768 dimensions, `embeddinggemma-2` plus its mmproj projector, provisioned as precompiled binaries with quarantine strip and `0755`.
